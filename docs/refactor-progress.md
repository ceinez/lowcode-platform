## 第 1 批：工程化基础 + 公告编辑闭环

批准日期：2026-11-17。目标仓库：`ceinez/lowcode-platform`，公开。

### 范围与验收

1. 编辑器、渲染端、共享契约和通信包组成独立 Monorepo。
2. 添加公告，修改文字与颜色，在 iframe 看到实时结果；可选中并删除公告。
3. 保存草稿后刷新可恢复；损坏草稿提示错误并打开空白页面。
4. lint、类型检查、核心契约单测、生产构建以及浏览器端到端测试通过。
5. 提交锁文件并配置 GitHub Actions，保证干净环境可重复安装。

### 本批技术决策

- 使用 npm workspaces：本机已有 npm，第一批减少额外包管理器依赖；保留文档要求的 Monorepo 包边界。原始技术方案中的 pnpm 尚未采用。
- 数据统一为 `schemaVersion: 1`、`components` 和节点 `type/props`；原始文档的 `componentList/data` 属于旧数据格式，本批不处理自动迁移。
- 公告先支持纯文本及两项颜色属性，不支持 HTML。文案使用 Vue 文本插值渲染。
- 注册元信息驱动表单；目前只有公告，后续新增组件需要补齐 Schema 判别联合和渲染映射。
- 公告最多一个，沿用旧项目的数量限制；没有虚设不可用的其他组件入口。
- iframe 接收消息时同时验证 `event.origin`、`event.source`、协议标记和消息数据；发送时使用明确的 origin。
- 预览 URL 通过 `editorOrigin` 指定父窗口。它是编辑预览配置，不是生产授权机制；正式发布与访问控制待后续设计。
- 草稿只手动保存到本地，不宣称已实现服务端持久化或自动保存。
- 第一批用原生表单元素和 CSS 完成界面；Element Plus、Vant、独立 components 包按后续批次需求引入。
